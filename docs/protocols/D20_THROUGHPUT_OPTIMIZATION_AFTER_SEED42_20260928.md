## 按顺序进行的检查

| 步骤 | 训练区测量与产物 | 继续条件 |
|---|---|---|
| 1. 找耗时环节 | 在训练区固定裁块/扰动序列做短测，分别计时CPU取样与缩放、主机到GPU传输、DINO前向、辅助/解码器前反向、优化器；另计完整开发评价的影像变换、推理及预测写盘耗时。记录每步中位/P95、显存和进程内存。 | 只有实测瓶颈，才选择相应优化。 |
| 2. 保持计算定义的实现优化 | 首选数据预取、固定采样索引、CPU pinned memory 和异步搬运；若 GPU 空间足够，再试训练影像缓存。评价可先测推理batch 4→8/16；P0的辅助扰动预测可复用经验证完全相同的clean预测。 | 同一输入、标签、裁块、扰动和模型权重下，输出类别图、整数CM及20步权重/损失与原实现一致；内存有余量；墙钟至少节省20%。 |
| 3. 改计算编排的可选版本 | 比较microbatch2×累积8与4×4、8×2，保持每步16个训练裁块及8,000步。记录采样索引、扰动、学习率、各组逐步耗时/峰值内存与数值差异。混合精度、TF32或`torch.compile`仅在前项收益不足且可验证时另列实验。 | 若梯度累积顺序、随机序列或权重轨迹变化，标为新协议版本；所有P0/P1/P2及需要的两个seed均从零按该版本重跑，不能接续旧检查点或把旧seed42和新seed17混为匹配复验。 |

优化判定用 **端到端墙钟**：训练、完整评价、读取/写盘和额外准备一起算。
只有至少约20%的可重复节省、无OOM、来源/路径边界合规，且不改变预设科学比较，
才值得切换。当前三组训练部分总关键路径约为P0/P1并行一轮加P2一轮，
因此应先看评价是否反而占主导；不要仅为提高GPU百分比增加计算量。
