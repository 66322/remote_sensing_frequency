# D23统一进度与结束时间查询

入口scripts/status_rebuild_v1_d23.py，只读本次队列状态、恢复事件、日志和完成标记，不加载checkpoint/预测、不调用GPU、不启动训练/评价、不新增资源审计。本地合成场景已确认恢复TS被正确覆盖、八组输出与2/8完成计数。

输出每组step/4000、eval/28、进程匹配状态、完整训练及评价完成组数。恢复事件的TS在合并前覆盖旧queue_status中失败TS，避免将旧失败状态误读为恢复未执行。训练日志每100步输出，因此步数可能落后不足100步；进程存在不证明持续推进，出现异常看对应日志。评价完成数按去重的tile/condition日志统计，28=两tile×14条件。

ETA为粗估：以已完成组training_complete.seconds和本次日志开始step计算每步耗时；以formal_complete.observed_at与服务器training_complete文件mtime之差估算整图评价耗时，取中位数。未来新组另给约2分钟初始化占位；训练、评价剩余量及每卡排队均计入。GPU0恢复合并前还计入TS/TF共同完成屏障。中心值与0.8–1.3倍时间范围是工程参考，不是统计置信区间或保证，假设后续无错误且连续执行；磁盘时间戳变更、初始化耗时和条件间速度会影响估计。

八组完成后仍检查screen_result是否生成；计算结束不代表八组筛选门槛通过。上传与GitHub记录遵循既有流程。所有服务器部署脚本落原zzx实验目录；可每60秒刷新，没必要每秒读取全日志。
