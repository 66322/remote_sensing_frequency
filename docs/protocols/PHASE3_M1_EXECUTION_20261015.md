## 双卡队列与共享计算

- 两张物理卡各一个持久worker，共享就绪任务队列；不设seed绑定或两卡等步数的屏障。空闲卡领取另一seed的下一项。
- 优先完成M11/M21两个seed的主要配对；C21仅由完整预设门槛触发，写明通过/跳过/失败，最多13个新训练、208k新更新。
- GPU完成clean logits交接后立即返回队列，CPU整数计数在独立线程池执行，不让GPU等待整图计数完成。
- 每个新的DSM端点立即得到主指标。已有绑定未变的旧M00/42不重训。
- 新训练暂时没有就绪任务时，空闲GPU处理已完成模型的尺度诊断、DSM故障诊断和旧锚点评估。
- 所有新DSM完成后，共享RGB故障前向，每个RGB条件只计算一次，供所有已完成DSM对照使用；不是每对模型重复跑RGB。
- 单个worker只保留一个当前冻结模型，连续RGB任务复用它，避免反复读取同一权重。
- 不用24/48小时硬终止，不为凑一天延长固定16k。真实ETA由正式训练轨迹给出。失败作业不自动重试，其他独立任务继续。

CPU处理采用固定FP64条带计算，保存充分整数联合计数。为明确数值实现，本执行包的固定融合统一为**先逐窗口FP32顺序拼接，再对累积logit做FP64的0.9/0.1混合**，并固定报告概率混合敏感性。这与Phase2.4 post-stitch静态参考的运算层次相同；不宣称等同逐窗口混合的逐位浮点舍入结果。此执行细节替代设计文档中“逐窗口混合后拼接”的数值措辞；所有新组采用同一实现，主DSM因子比较不变，不倒写旧门禁。

## 输入、数值与梯度核对

原始DSM TIFF和当前只读输入按已有SHA绑定核对；逐tile min–max结果必须逐元素等于原Phase2准备数组。R1/R2使用同中心和后续处理，只改变分母；S仅由Fit12计算。数据只允许Fit12和两张Val2。

高度值保持原数据单位，经过中位数中心化的表示不称nDSM/离地高度。空间尺度边界检查使用Potsdam原生5cm和抗混叠10cm版本；R2分母始终为训练Fit12常数，目标统计按实际采样版本计算。尺度诊断四格共用中央原生ROI，不与下采样恢复原尺寸的带宽退化混为一谈。

本机已检查实际MatchedExpert在微型encoder上的梯度：输入端确实改变，梯度穿过前八个冻结block，冻结权重保持不变。真实GPU检查并入首个实际更新，更新数计入16k；不单独开完整训练smoke。运行时检查有限梯度、stem实际更新及最终冻结权重不变。

服务器注册只执行新增Linux memfd传递定向检查，复用已通过且来源绑定的本机逻辑检查。Torch运行时要求沿用2.2.2+cu121。实际旧锚点CM、seed42流与旧初态在原有消费者中核对。旧锚点不满足匹配条件时，报告为历史非配对，主R1/R2比较仍成立，不自动补训旧基线。

## 缓存何时释放

| 产物 | 最后消费者 | 处理 |
|---|---|---|
| Fit12原始/规范化输入RAM | 全部主训练与已触发C21结束 | 父进程和两GPU进程分别释放，保存fit_ram回执 |
| clean DSM/RGB logits匿名RAM | 对应tile全部RGB条件的整数计数完成 | 引用计数归零即关闭memfd，不等另一tile结束 |
| 单个故障条件的临时RAM包 | 所有对照的该条件计数完成 | 即时关闭，不写磁盘预测 |
| 当前冻结模型GPU缓存 | 更换模型或GPU无后续任务 | 替换/退出时释放；CPU仍收尾时可先退出GPU进程 |
| last_resume.pth/优化器 | 16k权重和两个tile主计数持久化，训练作业已返回 | 核对端点SHA后删除，保留逐路径身份及回执 |
| CUDA/Torch/编译器缓存、临时目录 | 所有自有GPU/CPU消费者退出 | 完成、失败或中断收尾时清理 |
| 上传压缩包与独立Git对象副本 | 推送成功且全部文件回读一致 | 删除本run的upload_tmp并记回执 |

不生成整个8000/16000训练流的logit磁盘缓存，不保存所有条件的整图预测。正式16k必要权重、全部正负结果/失败证据、代码/配置/输入绑定、样本流、轨迹、整数CM与联合计数长期保留。失败作业的滚动恢复文件暂留，因其仍有排错/恢复用途，不按“主进程退出”误删。

清理白名单仅有本run的temporary、cache、upload_tmp以及jobs/<job>/last_resume.pth。拒绝符号链接、越界路径、最终权重和删除前已变化的文件。记录inode去重逻辑字节与磁盘前后值。仍有自有活worker时保持缓存并写cleanup_blocked回执，不写伪完成。
