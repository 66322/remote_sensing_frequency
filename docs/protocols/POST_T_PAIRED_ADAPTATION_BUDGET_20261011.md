## 1. 问题与固定候选

已验收M固定RGB专家包来源收益+2.901426pp、同S1-3解码器下两包收益+2.521564pp；但专家包含编码器及专家解码头，不能直接归因编码器。T1/T7后段收益+0.334083/+0.321695pp支持同预算研究。下一问题是：保持私有输出保护时，适应RGB编码器后的完整接口是否足够，加入最后4个编码块是否额外有效；收益是否只是预算/日程更长，以及固定模型是否对DSM内容敏感。开放尾部同时增加可训练容量，本轮不声称排除容量因素。

固定主候选R16。仅检验已知RGB局部缺失下的开发机制；DSM双向/未知故障/独立泛化贡献尚未成立。先做本轮定位，不预排镜像DSM、新频域/恢复方法或新种子。

## 2. 三机制×两预算：6项、72000新优化器调用

|机制|可训练RGB专家部位|可训练私有融合解码器|控制目的|8000|16000|
|---|---|---|---|---|---|
|F|无|是|普通私有解码适应控制|F8|F16|
|H|RGB专家net.rgb＋net.decoder[:-1]|是|编码器后完整接口适应控制|H8|H16|
|R|H全部接口＋encoder.blocks最后4块|是|事前指定RGB尾部适应候选|R8|R16|

F是新因子实验内的并行匹配控制，不能用旧T1的8000结果充当新配对，也不把旧T1/T7重训标为原失败门槛救援。F/H/R可训练容量不同，逐项报告有效梯度参数；H用于完整接口控制，R−H只能回答开放尾部在本配置下的增量。X8/X16移至RESERVED_NOT_AUTOMATIC，不计核心量或gate：空间打乱改变任务且可能被训练补偿，不能单独排除容量因素。没有随机初始化新分支、S1-3迁移初值或选择更高分M303。

## 3. 单一初值、输入与实际执行链

所有6项从同一个已绑定S1-0 step8000 state开始，重新初始化优化器、训练step归零；私有RGB副本与融合解码器均复制S1-0，禁止从T7/4000/旧8000优化器续跑。S1-0 SHA=5a8cd5c40576e1897fbb6a767dd2028016df402c2b3b6ae98994f55ac4cec58f；原路径与输入manifest、fit12名单、锚专家/数据SHA完整继承57ef5ad9原件plan.json。发布可执行包时逐字段冻结JSON，不能仅写“同上”。

原S1-0完整基座冻结。私有RGB专家副本：前8块、patch embedding及编码器其他部位冻结；F全冻结，H开启net.rgb与net.decoder[:-1]，R在H基础上开启最后4块。真实RGB最终分类器是net.decoder[-1]，hook捕获其输入；它不参加私有特征loss，必须冻结。net.rgb是编码特征投影而非分类器。冻结前后名单和有效梯度名单逐项验证，避免假容量。DSM完整专家冻结。私有融合层为project_rgb/dsm、merge_rgb/dsm、fusion。禁止未经名单核验调用configure(True)后声称仅RGB适应，它还会开启DSM或最终分类器。

实际受损RGB/DSM按报告掩码清零，供RGB/DSM真实前向。保留上下文的A1B0C0仅改变进入私有融合解码器的特征支持策略，整窗全缺失保留原回退。F/H/R私有RGB特征均保持原空间对应。新增DSM内容诊断只在固定模型推理时干预送入候选融合分支的DSM pre-classifier特征，基座、掩码和路由不变；定义、24前测＋24后测及验收见研究排期。它是内容敏感性诊断，不能替代真正RGB-only匹配训练。

原基座产生全条件安全输出，私有分支只覆盖RGB缺失且DSM可用且窗口存在可见RGB的区域；native在相同512/256拼接后应用预定observable_window支持与S1-0输出路由，支持外逐像素等于基座。普通/全缺失/DSM_U均按原回退，不依赖标签或oracle。所有臂保留同一逻辑前向图：原基座RGB/DSM＋私有RGB副本；允许F复用完全相同特征，但必须报告实际前向数与耗时。暂不宣称共享前8块、单RGB前向或计算优于R0；共享早期计算属于后续优化，不能在本轮悄然变更图。

冻结own logits从原基座返回，clean/aug own CE不向私有专家反传。6项使用完全相同旧support_objective：每view 0.5 CE(fusion,valid)＋0.125(CE(base_rgb,rm)＋CE(base_dsm,dm))，clean＋aug相加，沿旧ce原始分母归一化；融合CE只有路由支持内向私有参数产生梯度，基座项为常数。不要新增head-only监督/KD、增大支持权重或只在R使用额外全图训练。每臂记录非零更新数、每view有效/支持像素分母及梯度名，梯度名不得仅通过参数计数推断。

## 4. 预算、随机流和优化器

Potsdam fit12→Val2=3_11/5_10，seed42、physical_batch=16、clean＋aug两view、无梯度累积、train BF16/eval FP32+TF32，原crop/退化/可用性概率及本地缺失形状完整继承。各臂训练数据随机流按(seed42,step,sample_id)独立于模型dropout RNG固定，同预算臂逐step batch/增强散列相同；16k与8k前8000个batch一致，16k后8000为预定新样本流，不复制一遍旧8000。

AdamW：encoder尾4块LR=2e-5，RGB投影net.rgb、专家decoder[:-1]和私有融合decoder LR=2e-4，betas=(0.9,0.999)，wd=0.01。按显式完整参数名分组，不能照搬只识别旧rgb_expert前缀的分组函数而让新private_rgb编码器误用head LR。warmup100，factor=.1+.9*t/100(t≤100)，之后(B-t)/(B-100)，B=8000或16000；每个预算组同一日程从step0开始。8k和16k在前8000 LR不同，这是预算×日程联合干预，不能把差异命名为纯更新次数作用。禁止末端LR=0的旧checkpoint原地延长。

每500保存恢复状态，每4000保存绑定checkpoint并做Val2 RGB_U/DSM_U和保护检查。主机制/预算比较使用预定fixed endpoint B，不做test选模；另外只用validation从4000,8000(及12000,16000)选择保护条件合格且RGB_U最高checkpoint，相同分数选较早步。selected结果次要单报，不与fixed budget混算；最终用途先报告选模次数和开发集重复使用边界。全部评价为Val2，无Test6/held4/final。
