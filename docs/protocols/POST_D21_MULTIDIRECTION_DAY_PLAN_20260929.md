# D21 后多方向单种子实验计划

状态：对照方案已冻结，[执行代码与操作说明](POST_D21_DAY_EXECUTION_20260929.md)已准备；服务器预检、短测和正式训练仍未进行。所有新设置均属**重写版建议**，不能作为已验证结果。用户要求 GPU0/1 连续实验至少一天，允许更久；本计划目标为24–48小时，所有探索默认 seed42。范围为42项主训练及8项预先列明的备用训练，不启动第三种子。

## 为什么调整方向

D21 显示细尺度 DSM 有开发增益，F2 在四个数据集×种子块方向一致但未过冻结门槛；缺失 DSM 与部分 Vaihingen tile 仍受损。吞吐短测说明可以增大微批，但当前只有冻结 F2 的六步数据，不能证明新架构的耗时。

不能据此只在同一轻量冻结头上继续堆门。D9B 的固定输入边缘对齐评分、D13 的风险抑制残差、D16/D17 的一致性/梯度监督和 D19 的具体局部交互变体均有负结果。上一版 D22 固定 Sobel 门草案因此不作为主训练方案；本计划改为学习型 RGB 条件残差，并安排容量、原始高度及高频位置打乱对照。旧草案保留为历史建议，不实现其固定门主线。

当前需要分开回答：表征能否适应任务；高度信息怎样进入空间特征；低分辨率输入是否需要真实恢复；恢复与高度是否互补。各方向结果分别报告，不能跨起点或任务设置直接拼成一个排行榜。

## 共用边界

- 两个数据集分别作为研究区块：Potsdam Train16/Val2，Vaihingen 12训练块/17同镶嵌图开发块。Test6/独立 final 继续封存；全部是开发证据，两个数据集也不是随机种子的替代品。
- 主指标：Potsdam NoBoundary fg5 mIoU；Vaihingen FullGT fg5 mIoU。保留全6类诊断、每类计数、每 tile int64 6×6、边界计数、条件与 checkpoint SHA。不得把像素、裁剪或同镶嵌图 tile 当作独立重复计算显著性。
- 每个比较组固定样本键、增强、退化、有效 batch16、优化器/调度、起点及预算；seed42同时用于所有必要对照。队列顺序随机但可复现，物理GPU分配在设置之间均衡，避免某方法固定占某张卡。
- 每个新方向默认固定最终步 checkpoint，不根据反复查看开发分数提前挑权重。训练损失/梯度可以用于故障检查，不用 test 选模。
- `16×1` 仅为暂定打包；根据实际新模型短测选择微批与累积，乘积保持16。同一比较组使用相同精度与归一化。若采用 BF16，先检查有限梯度、损失及更新，整组统一；失败则整组 FP32，不给单个候选特殊设置。
- 优先复用已有 d18_dino、DINOv2 ViT-S/14 源码/权重、D21 checkpoint 和现有数据。主计划没有新增数据集、权重或软件包下载。发现缺项时先报明路径、来源、大小及访问路线；下载和训练分开。

## A：表征适配 × 辅助模态，12项

问题：冻结 DINO 是否限制细节和模态收益？解冻后的提升是否只是 RGB 主路径变强？

完整 `2×3` 因子组合，在两个数据集各执行一次：

| 因子 | 水平 |
|---|---|
| 编码器适配 | 全冻结；仅最后4个 transformer block 可训练 |
| 输入/辅助支路 | R0 光学；M1 光学+灰度容量对照；M0 光学+原始 DSM |

每个模态从对应 D21 seed42 的16k最终 checkpoint 出发，分叉成两个适配水平，各**继续8k**；同一对从完全相同的参数与重置优化器状态开始。冻结组的8k是必要的继续训练对照，用于隔离“多训练8k”和“解冻”的效应，不重跑原16k。预训练编码器采用一个固定小学习率，头部采用一个固定学习率，不扫网格；数值在训练前配置中冻结。

共12项，合计96k新更新。分析同一模态的解冻增量，以及 `(解冻DSM−解冻灰度)−(冻结DSM−冻结灰度)`。这里检验的是训练策略和交互作用，不能将“解冻有用”本身作为论文新模块。方向无改善时，不再追加解冻层数或学习率搜索。

## B：RGB 锚定的学习型细尺度 DSM 残差，8项

问题：在保留光学路径的条件下，RGB 条件空间残差能否利用高度并减少损害？

固定每个数据集既有 D21 R0 seed42 为锚点，冻结 encoder、RGB adapter 和 decoder；仅训练新增1/4尺度残差头16k。头部接收冻结 RGB 特征和两个辅助通道，所有设置使用同一结构、宽度、初始化与参数量；不采用固定 Sobel 可靠性门。

| 设置 | 两个辅助通道 | 作用 |
|---|---|---|
| B1 | RGB 灰度与零通道 | 匹配额外容量，排除仅靠 RGB 分支增容 |
| B2 | 原始 DSM 与零通道 | 原始高度基线 |
| B3 固定候选 | DSM 低频与高频 | RGB 条件的细尺度频率残差 |
| B4 | DSM 低频与空间滚动后的高频 | 位置对应消融，保持高频直方图 |

共4设置×2数据集=8项，128k更新。每个设置末端共享相同的显式“整幅 DSM 缺失”回退规则，包括灰度容量对照，确保安全机制不是候选独享。这个输入约定须单独记录；合成零填充回退成功不能声称学会了真实缺失检测。局部缺失、低质量高度和错位下的可靠性仍须实际评价。

B3 对最强 B1/B2/B4 的综合增益须分别达到 +0.2 pp，同时保留既有 clean/家族/逐tile保护；冻结主路径且缺失时残差为零，应先通过与 R0 logits 相同的实现门禁。边界、harm/rescue 辅助解释，不以安全回退的零误差替代可用 DSM 的收益。D13/D9B 的失败限制要一起报告；新分支未通过则关闭具体设计。

## C：真实低分辨率恢复 × 恢复目标 × 退化倍率，16项

问题：分割需要可学习的恢复前端吗？收益来自额外容量、像素恢复，还是高频恢复？这条线直接服务第2章及第4章之间的关系。

每个训练裁剪先按固定规则降为2倍或4倍低分辨率，输入仅有低分辨率光学影像，监督标签保持目标512尺度。两个倍率分别立项，不在同一结果中混称原分辨率 clean。学习型恢复前端输出512尺度图像，再进入同一个分割器。

| 设置 | 前端与损失 | 核心对比 |
|---|---|---|
| C0 | 固定双三次恢复 + 分割 CE | 无可学习恢复基线 |
| C1 | 可学习恢复 + 分割 CE | 容量与任务驱动恢复 |
| C2 | 与 C1 相同 + 像素 L1 恢复 | 像素重建的额外价值 |
| C3 固定候选 | 与 C2 相同 + 高频残差 L1 恢复 | 高频目标是否超出像素目标 |

4设置×2倍率×2数据集=16项，每项16k，共256k更新。C1/C2/C3的前端结构完全相同，额外损失没有额外可训练头；恢复损失仅在训练使用对应原始 HR 裁剪，验证/推理不能向网络提供 HR 图像。辅助损失系数先按训练尺度确定并在全部条件统一冻结，不使用 Val2 扫权重。

分割器从现有通用 DINO 预训练权重和共同新头初始化，暂定仅最后4个 block 可训练。**冻结权重不等于关闭对输入的梯度**：恢复前端必须同时收到分割 CE 与恢复损失的反传；不得在恢复前端到分割输出的链路中套 `no_grad()`。这与旧 D17 的辅助 DSM 梯度监督是不同任务，不能照搬其失败配方。

C3 主要与更强的 C1/C2 配对，主判仍是对应 LR 任务的分割改善，不以 PSNR/重建 L1 下降替代分割收益。记录固定算子的高频误差、边界 F1、逐类 IoU；倍率依赖性如实报告。C0/C1单独区分可学习前端及容量效应，C1/C2/C3隔离目标项。各组16k固定预算，不能只给候选延长训练。

## D：恢复目标 × DSM 辅助的交叉验证，新增6项

问题：恢复和高度互补，还是在补偿同一种细节信息？在两数据集各自的4倍 LR 任务上构成完整 `2×2`：恢复目标采用 C1（只有 CE）或 C3（CE+像素+高频）；辅助采用无 DSM 或 RGB 条件 DSM 分支。

无 DSM 的两个单元**直接复用 C1/C3 的4倍训练任务**。新增“C1+DSM”“C3+DSM”，每数据集2项；再新增“C3+灰度容量对照”，每数据集1项。合计6项，每项16k，共96k更新。

所有新增组从与 C 组相同的起点训练，采用相同样本/预算/恢复前端/精度；只在指定位置增加辅助输入。复用的是 B 的结构定义而非 B 的 checkpoint；这条端到端比较不沿用 B 的冻结 R0 回退保证。

报告交互量 `[(C3+DSM)−(C1+DSM)]−[C3−C1]`，及 C3+DSM 对 C3+灰度的增量。交互为正只能说明本 seed、开发数据下互补的迹象，不是统计显著性结论。也评价 DSM 缺失/局部缺失，完整报告组合是否引入额外风险。无须等某组成为“赢家”才选择组合，C1/C3及 DSM 分支在启动前固定。

## E：预先定义的备用问题，8项

若准备阶段实测主计划不足24小时，优先纳入本块：C0–C3 在两个数据集上采用**同一固定分布的混合倍率/模糊退化训练**，各16k，共8项。具体倍率/模糊核/抽样概率在训练前冻结；评价覆盖预设倍率及训练中未出现的一个模糊强度，不能从开发效果挑最有利组合。它检验恢复方法对训练退化假设的依赖，区别于 C 的固定2倍/4倍训练。

备用块在看主实验准确率之前按吞吐和剩余预算选择是否纳入，纳入后执行完整四组，不能只追加候选。不得用补随机种子、调高失败组步数或无意义重复填满一天。若主计划本身超过一天，本块可以留到下一阶段。

## 工时和双卡顺序

主计划42项、新更新共576k；加备用块为50项、704k。每项均单 seed42，某些组是8k续训，不能只按任务数比较计算成本。D21 六步短测的0.154秒/步只适用于那个冻结 F2 条件，不能推广给需对图像反传的 C/D。

下表是**计划时间窗口，不是实测 ETA**。T=0 指代码、资产及协议准备就绪后的服务器开始时间，不把写代码或等网络的时间算进“一天实验”。

| 暂定窗口 | 两卡安排 | 输出 |
|---|---|---|
| T+0–1h | 对 A 的冻结/解冻、B、C/D 各测代表路径；两卡同时负载短测 | 每步/加载/评估/保存耗时，数值检查，CPU等待与峰值内存 |
| T+1–8h | A/B 匹配块交错执行，一卡一任务；同模型不固定绑某卡 | 表征适配与安全残差两条证据 |
| T+8–24h | 两卡继续 C 的完整倍率×目标矩阵 | 真实恢复目标和分割收益的关系 |
| T+24–36h | 完成 C，执行 D 的交叉单元 | 互补/冗余与容量对照 |
| T+36–48h 或更久 | 按准备时冻结范围完成剩余任务；必要时执行 E | 完整配对结果和汇总 |

执行前用实际测量 `训练步数×秒/步 + 加载 + 保存 + 全条件评估`，结合双卡依赖顺序估算队列。以**预计至少24小时**作为范围冻结条件，优先42项主计划，需要时加完整E块；若新模型更慢则允许越过48小时。若全部有研究价值的预定义任务在实测后仍少于24小时，明确报告实际预计时长并补充有独立问题的设计，不声称已满足时长，也不人为限速或空转。真实运行仍可能因故障提前退出，不能保证墙钟时长。

初次开启前一次性说明设备、任务量、预计时间、磁盘和内存保护阈值。准备完成后队列按冻结范围自动推进，无需逐组询问。默认每卡一个训练进程，不因显存空闲随意多开并发；是否并发只可由专门吞吐比较决定。

## 停止和产出

- 实现/资源失败（非有限梯度、锚点/输入校验不符、数据越界、磁盘不足）停止受影响块并保存日志；若数据或共用代码不可信，停止整个队列。一个方向效果差不阻断其他独立方向。
- 不按单次中途开发分数淘汰对照；比较块完整完成后判定。技术故障可恢复原任务，不能重采样或换 seed 找更高分。
- A 的适配效果、B 的安全性/频率增量、C 的恢复目标、D 的交互分别出表，保留全部对照与失败 tile，不把最好的若干格拼成总体成功。
- D21现有门槛和失败记录不改写。B保留+0.2 pp候选门槛及原保护条件；C/D在实现时为对应LR任务单独冻结主指标、对照和保护门槛，未冻结前不能训练。
- 主机内存、显存和磁盘按新模型短测及输出大小计算；不沿用“48 GiB必然消耗”或“120 GiB必然需求”。只把精简指标、计数、配置、版本与定位索引同步 GitHub，权重和大预测保留服务器。
- 多 seed 仅在具体需要区分随机波动、方向冲突或确认性报告时另立项，必须候选与必要对照成对复验；本队列不自动追加。
