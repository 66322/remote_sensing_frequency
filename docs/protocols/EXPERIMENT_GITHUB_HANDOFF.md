# GitHub 跨电脑实验交接：最低证据要求

GitHub 是两台电脑判断实验效果和规划下一步的共同依据。服务器保留原始数据、
检查点、预测数组和完整运行日志；GitHub 必须保留足以独立重算关键指标、
核对预设门槛并识别缺项的紧凑证据。路径和 SHA256 只说明产物身份，不能代替结果。

## 每轮结束后的 GitHub 内容

1. `records/<实验编号>_compact_<日期>/`：保存原始队列 `status.tsv`、预设筛选
   与最终 `decision.json`、每个正式组的评估 `summary.json`。保留完成、失败、
   阻塞和条件跳过的全部组，不能只上传表现最好的候选。若某个 summary 缺失，
   在清单中写明原因。文件名标明服务器原件或用户转录，不能混称独立复算。
2. 逐组摘要应包含数据划分与评估条件、主指标及其单位、各条件/类别/tile
   结果、整数混淆矩阵或足以重算指标的原始计数、harm/rescue/覆盖率等
   协议要求的安全指标、与匹配对照的差值及每条门槛的通过情况。
3. `docs/experiments/<实验编号>_RESULTS_<日期>.md`：写清研究问题、全部
   对照、训练预算和选模规则、结果总表、预设门槛的逐项判断、失败原因、
   证据等级与局限，以及明确的继续/停止决定。单 seed 和反复使用的 Val2
   只能标为探索证据；不得把 Test6 未使用写成独立验证通过。
4. 记录可复核的身份信息：执行 Git 提交、配置与源码哈希、数据划分、权重
   文件在服务器上的路径/大小/SHA256、完成时间和 GPU。大的文件留在
   `/home/jovyan/zzx`；其路径不得指向该边界之外。
5. 更新 `docs/current/HANDOFF.md`、`PROJECT_STATUS.md`、
   `NEXT_EXPERIMENT.md`、`DO_NOT_REPEAT.md`、实验索引和 JSON 登记表，
   让另一台电脑从 GitHub 即可知道本轮是否结束、哪些结论成立及下一步。

## 关闭前核对

核对队列逐项状态与 summary 数量，重算可重算的主指标和门槛，并区分
`COMPLETE`、`FAILED`、`BLOCKED`、`SKIPPED`。不能用 `QUEUE FINISHED`
代替所有正式组完成。缺少足以判断结论的原始计数或对照时，标记证据不完整，
先补齐归档，再规划复验或新实验。提交并推送后确认远端提交可见。

不上传原始数据、模型权重、完整 `runs/`、预测 npz 或冗长训练日志；
这不减少上述结果、计数、判断和下一步的归档要求。
