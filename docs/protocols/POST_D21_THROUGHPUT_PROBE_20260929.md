# D21 训练入口的有界吞吐测试

## 目的与边界

只测试现有 F2 细尺度模型在服务器上的实际训练与全图推理吞吐，确定下一批的微批与累积候选，并区分数据准备和 GPU 计算耗时。使用 Vaihingen **训练块**、单种子42和一张空闲卡；不读取开发标签、独立 final 或 Test6，不写 checkpoint，也不按结果选模型。不是 D21 的追加准确率实验。

## 预检与资源

- 环境：复用已有 `d18_dino`、DINOv2 本地源码及权重、Vaihingen 训练数据。脚本只检查存在与可用性；不会安装或下载。若缺失，停止并先报告所需文件、来源、大小、网络路径和中转方式。
- 设备：默认物理 GPU0，可改传 `1`；只使用一张卡。启动前要求该卡显存已用≤1500 MiB、利用率≤10%，主机可用内存≥48 GiB。GPU1可以留给其他工作。
- 时间：候选 `2×8、4×4、8×2、16×1`，每项2步预热、6步计时；脚本内部20分钟上限、外层25分钟硬停止。实际用时应以服务器记录为准。若 OOM，记录并继续；到时间上限即停止。
- 空间：只输出一份 JSON、一份每秒 GPU 利用率/显存/功耗采样 CSV 与终端日志，无模型或预测文件，新增磁盘量预计小于1 MiB。已有训练数据被加载到主机内存，实际峰值由结果记录。显存 allocated/reserved 与整卡占用口径分开保留。

## 操作

在服务器仓库拉取此协议所属提交后，确认 GPU0 空闲，再运行：

```bash
cd /home/jovyan/zzx/paper_rebuild/08_thesis_full_repro
git pull --ff-only origin rebuild-v1-protocol-20260915
mkdir -p records/rebuild_v1_d21_throughput_probe_20260929
set -o pipefail
bash scripts/run_rebuild_v1_d21_throughput_probe.sh 0 \
  | tee records/rebuild_v1_d21_throughput_probe_20260929/gpu0_probe.log
```

若 GPU0 忙而 GPU1 空闲，将最后参数改为 `1`，日志名相应改为 `gpu1_probe.log`。命令不会启动正式队列。结束后将对应的 JSON 和 `gpu0_telemetry.csv`（或 GPU1 文件）提交到当前 GitHub 分支，或回传这两份文件及终端末尾输出；先审查瓶颈和数值风险，再冻结正式配置。

## 比较口径

四候选每步使用同一组16个单样本裁剪与退化键，总有效 batch 固定16。每项重新从同一预训练权重构建模型，并执行真实前向、反传和优化器更新。分别记录数据准备与传输时间、GPU 同步后的训练计算时间、有效样本/秒、显存 allocated/reserved 峰值及主机内存峰值。随后在一块**训练图**上走完整 `infer_tile` 路径，记录推理耗时和吞吐，不读取其标签。

测试为了让四种分组共享样本流，采用逐样本生成再拼接；它与 D21 原始“每微批一次裁剪和增强”的执行方式不完全相同。不同微批的 CE 有效像素分母、浮点归约和批依赖行为也可能不同。吞吐优胜配置需另做短时数值/梯度与训练稳定性检查，不能直接宣布与 D21 等价或复用 D21 已归档指标。若数据准备占主要时间，再单独设计预取测试；此脚本没有声称已优化 DataLoader。
