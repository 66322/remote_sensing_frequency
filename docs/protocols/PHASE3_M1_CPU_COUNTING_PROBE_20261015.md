# Phase3-M1 CPU统计加速对照（2026-10-15）

性质：独立性能诊断，尚未应用到正在运行的实验，不改变模型、训练、原计数证据或门禁。

用户最新诊断：统计池16线程，启动时记录192有效CPU，可见affinity为192，控制器实际约10.03核，进程22个OS线程、RSS 29142472 KiB，完成127/320案例。未显示cpu.max，因此192不能直接解释为可用CPU配额。原profile仅读cgroup v2，独立工具同时核查v1/v2及其可见祖先限额。

入口为固定提交的 scripts/benchmark_phase3_m1_counts.py --directory <当前恢复run>。代码只读取当前run的状态、配置和不可变计数源码，不向其发信号、不改变线程池、不写结果、不重启任务、不使用GPU，不扫描或删除缓存。若实验已结束、接近完成、CPU配额无余量或空闲主机/容器RAM不足12GiB，打印原因并退出。

对照用独立进程内合成的256x6000条带、4案例x12模型，保持与实际统计相同的图像宽度和128行切片方式；不读取遥感像素或checkpoint。分别测试原计数器和合并ROI直方图计数器的16/24/32线程，并限制测试线程数不超过可见CPU配额扣除当前线程数后的余量。每配置2次，第二轮反向顺序；先预热依赖，避免把第一次导入耗时算成算法加速。CPU及内存带宽仍与当前任务共享，因此结果是并行运行条件下的合成性能参考，不是实际完整tile的结束时间承诺。

合并ROI只减少重复像素扫描：保留原FP64 logit/概率融合及argmax顺序，用健康/损伤两个bit编码4类支持区域，一次直方图还原all/healthy/damaged三张联合表。重叠和边界过渡区域也完整保留。输出仍包含full/noBoundary、各系统的6x6x6联合表、CM、救回和损伤。

本机两个测试通过：覆盖36组不同尺寸/跨条带/忽略标签/ROI重叠/缺失回退/边缘排除/并列值配置的全部嵌套输出逐值相等，以及非有限logit拒绝；另用实际6000像素宽度检查结果一致。排除导入预热后，本机单线程ABBA小样本观察原实现2.505/3.136秒，合并实现2.058/1.929秒。这只能支持在目标服务器实测，不能承诺对应比例加速。

只有目标对照输出BENCH_SUMMARY且全部integer_evidence_exact为true后，才评价增加并发或更换算法的收益。工具本身不执行切换。当前没有热修改线程池入口；如将来需要切换，必须复用已完成案例并核对来源、保留当前运行记录，不能为加速重做全部推理。若剩余工作较少或收益不足，继续现有队列。
