# Post-T下一轮：RGB专家适应位置×预算配对训练协议

状态：PLANNED_NOT_IMPLEMENTED_NOT_REGISTERED。属于重写版建议；用户要求诊断后制定，当前仅冻结研究设计，不意味着训练实现、GPU验收或排队。不能把本轮8配置计为已运行，也不自动重跑任何旧T配方。

## 1. 问题与固定候选

已验收M固定RGB专家包来源收益+2.901426pp、同S1-3解码器下两包收益+2.521564pp；但专家包含编码器及专家解码头，不能直接归因编码器。T1/T7后段收益+0.334083/+0.321695pp支持同预算研究。下一问题是：保持私有输出保护时，适应RGB专家解码头是否足够，加入最后4个编码块是否额外有效；收益是否依赖正确空间表征，以及是否只是预算更长。

固定主候选R16。仅检验已知RGB局部缺失下的开发机制；DSM双向/未知故障/独立泛化贡献尚未成立。先做本轮定位，不预排镜像DSM、新频域/恢复方法或新种子。

## 2. 四机制×两预算：8项、96000新优化器调用

|机制|可训练RGB专家部位|可训练私有融合解码器|控制目的|8000|16000|
|---|---|---|---|---|---|
|F|无|是|普通私有解码适应控制|F8|F16|
|H|RGB专家中产生pre-classifier特征的net.decoder|是|专家解码头/接口适应控制|H8|H16|
|R|上述net.decoder＋encoder.blocks最后4块|是|事前指定RGB尾部适应候选|R8|R16|
|X|与R完全相同|是|等参数/等预算空间对应控制|X8|X16|

F是新因子实验内的并行匹配控制，不能用旧T1的8000结果充当新配对，也不把旧T1/T7重训标为原失败门槛救援。R和X trainable_names/numel及有效梯度参数必须相等，F/H容量自然不同并逐项报告；H用于定位适应位置，X用于排除只增加容量。没有随机初始化新分支、S1-3迁移初值或选择更高分M303。

## 3. 单一初值、输入与实际执行链

所有8项从同一个已绑定S1-0 step8000 state开始，重新初始化优化器、训练step归零；私有RGB副本与融合解码器均复制S1-0，禁止从T7/4000/旧8000优化器续跑。S1-0 SHA=5a8cd5c40576e1897fbb6a767dd2028016df402c2b3b6ae98994f55ac4cec58f；原路径与输入manifest、fit12名单、锚专家/数据SHA完整继承57ef5ad9原件plan.json。发布可执行包时逐字段冻结JSON，不能仅写“同上”。

原S1-0完整基座冻结。私有RGB专家副本：前8块、patch embedding等早期部位冻结；F全冻结，H只开启net.decoder，R/X开启net.decoder＋最后4块。RGB最终分类器不参加私有特征路径的loss，保持冻结，避免“requires_grad=True但没有梯度”的假容量。DSM完整专家冻结。私有融合层为project_rgb/dsm、merge_rgb/dsm、fusion。禁止未经名单核验调用configure(True)后声称仅RGB适应，它还会开启DSM或最终分类器。

实际受损RGB/DSM按报告掩码清零，供RGB/DSM真实前向。保留上下文的A1B0C0仅改变进入私有融合解码器的特征支持策略，整窗全缺失保留原回退。私有RGB特征在正常空间位置输入H/R；X对该特征图沿H/W各循环平移floor(size/2)，每个crop确定且不读取标签，固定反例同时用于训练及评价。X其他输入、mask、卷积、loss、优化器和参数量与R一致。它只能检验正确空间对应对该新适应路径的作用，不能当作真实缺失分布或DSM内容有效性的证明。

原基座产生全条件安全输出，私有分支只覆盖RGB缺失且DSM可用且窗口存在可见RGB的区域；native在相同512/256拼接后应用预定observable_window支持与S1-0输出路由，支持外逐像素等于基座。普通/全缺失/DSM_U均按原回退，不依赖标签或oracle。所有臂保留同一逻辑前向图：原基座RGB/DSM＋私有RGB副本；允许F复用完全相同特征，但必须报告实际前向数与耗时。暂不宣称共享前8块、单RGB前向或计算优于R0；共享早期计算属于后续优化，不能在本轮悄然变更图。

冻结own logits从原基座返回，clean/aug own CE不向私有专家反传。8项使用完全相同旧support_objective：每view 0.5 CE(fusion,valid)＋0.125(CE(base_rgb,rm)＋CE(base_dsm,dm))，clean＋aug相加，沿旧ce原始分母归一化；融合CE只有路由支持内向私有参数产生梯度，基座项为常数。不要新增head-only监督/KD、增大支持权重或只在R使用额外全图训练。每臂记录非零更新数、每view有效/支持像素分母及梯度名，梯度名不得仅通过参数计数推断。

## 4. 预算、随机流和优化器

Potsdam fit12→Val2=3_11/5_10，seed42、physical_batch=16、clean＋aug两view、无梯度累积、train BF16/eval FP32+TF32，原crop/退化/可用性概率及本地缺失形状完整继承。各臂训练数据随机流按(seed42,step,sample_id)独立于模型dropout RNG固定，同预算臂逐step batch/增强散列相同；16k与8k前8000个batch一致，16k后8000为预定新样本流，不复制一遍旧8000。

AdamW：encoder尾4块LR=2e-5，专家pre-classifier decoder和私有融合decoder LR=2e-4，betas=(0.9,0.999)，wd=0.01。按显式完整参数名分组，不能照搬只识别旧rgb_expert前缀的分组函数而让新private_rgb编码器误用head LR。warmup100，factor=.1+.9*t/100(t≤100)，之后(B-t)/(B-100)，B=8000或16000；每个预算组同一日程从step0开始。8k和16k在前8000 LR不同，这是预算×日程联合干预，不能把差异命名为纯更新次数作用。禁止末端LR=0的旧checkpoint原地延长。

每500保存恢复状态，每4000保存绑定checkpoint并做Val2 RGB_U/DSM_U和保护检查。主机制/预算比较使用预定fixed endpoint B，不做test选模；另外只用validation从4000,8000(及12000,16000)选择保护条件合格且RGB_U最高checkpoint，相同分数选较早步。selected结果次要单报，不与fixed budget混算；最终用途先报告选模次数和开发集重复使用边界。全部评价为Val2，无Test6/held4/final。

## 5. 固定比较、指标与去留

主指标NoBoundary pooled mIoU_fg5，由两tile int64 6×6先相加再算。保存Full/fg6、逐类TP/FP/FN/IoU与分母、逐tile/条件、支持内救回/伤害和预测/输入/checkpoint/代码绑定。

固定主比较R16−F16≥0.3pp且两tile正；编码尾部增量R16−H16≥0.3pp且两tile正；正确空间表征增量R16−X16≥0.3pp且两tile正。三者分别回答参数位置、普通适应和空间对应，不能择优只报一项。R16相对已验R0 RGB_U不低于−0.2pp；clean、RGB全缺失、DSM全缺失、DSM_U对基座≥−0.1pp，普通primary最坏tile≥−0.2pp；六E各不低于基座−0.1/R0−0.2pp及原worst-tile≥−0.2pp。路由支持外与冻结基座状态必须exact。R0仍是已知掩码双模型参考，不把成本视为与8个新训练相同。

完整报告每机制16−8、每预算R−F/R−H/R−X以及差上差(R16−R8)−(F16−F8)。预算收益规划门槛：F和R的16−8都≥0.3pp且各自两tile正；只有R上升不能声称普遍欠训练。差上差单报，不靠它自动承诺16000是最优预算。阈值为开发效应量与工程取舍，单seed/两个tile无统计显著性或独立泛化承诺。

若H接近R或R−H未过，优先保留更简单专家解码头方案，关闭本轮“尾4块独立增量”承诺；若R≈X，关闭正确空间对应的新增承诺；若F16≈R16，普通解码适应/预算足以解释；若R过增量却未过R0/保护底线，仅保留机制线索，不能发布成功候选。整轮不后验换H/X为成功方法、不加seed、不扫步数/尾块数/损失，也不重跑失败臂。
