# 下一步：吞吐测试与新机制立项

D21 已在有效双种子范围完成，[结果](../experiments/D21_DETAIL_FREQUENCY_RESULTS_20260929.md)未通过冻结门槛。不要再补第三种子或用开发集重调 F2 门槛。

1. 先填写[实验准备表](../templates/EXPERIMENT_PREFLIGHT_TEMPLATE.md)，核对服务器 GPU0/1 当前空闲、已有数据和环境。声明测试时间上限、资源与停止条件；若需新下载或安装，先单独说明来源、大小和访问路径。
   [第一阶段短测](../experiments/POST_D21_THROUGHPUT_PROBE_RESULTS_20260929.md)已由用户执行并回传；原始 JSON 与整卡采样 CSV 待同步。`16×1` 及 `8×2` 为后续核对候选，不因六步计时直接修改正式配置。
2. 将 `16×1` 作为下一批的暂定吞吐配置；在正式训练前的短流程中核对损失、梯度、更新和稳定性，不通过则回退至吞吐接近的 `8×2`。GPU 采样文件可并行归档，不阻塞新机制设计。
3. 根据 D21 的 DSM 缺失退化和 Vaihingen 失败 tile，提出有明确输入输出与对照的新可靠性机制。探索默认单种子42，候选与必要基线同预算；预先冻结准确率、逐tile和缺失 DSM 门槛。
4. 仅在开发结果达到预设门槛后规划独立地区/来源验证。Test6 不用于当前选模。GAMUS 并非必选；任何新来源先完成来源、类别和空间划分验收。

性能测试只回答吞吐配置问题，不能作为准确率增益证据。完成测试后再根据实测吞吐估计正式队列时长并排队。
