# D21 F2 单卡吞吐短测结果

## 证据范围

用户回传了服务器终端输出；其中完整 JSON 逐字段保存为[用户粘贴的结果](../../records/rebuild_v1_d21_throughput_probe_20260929/user_pasted_gpu0_F2_vaihingen_seed42.json)。服务器原始 JSON 和每秒 `nvidia-smi` 采样 CSV 尚未同步到 GitHub。本记录是**性能短测证据**，不是准确率实验或最终配置验证。回传文本未显示运行的绝对时间；可核对的运行提交为 `8f315d2`，测试自身耗时18.40秒。

测试对象为 Vaihingen 训练区、F2、seed42、有效 batch16、H100 80GB 的物理 GPU0。每候选2步预热、6步计时，四候选共享逐样本裁剪和退化键。训练计算包括真实前向、反传和优化器更新；全图推理仅用一块训练图，不读取开发或 Test6 标签。

| 微批×累积 | 数据准备/传输 秒/步 | 训练计算 秒/步 | 合计 秒/步 | 有效样本/秒 | CUDA allocated 峰值 MiB | CUDA reserved 峰值 MiB |

`16×1` 相对原 `2×8` 的短测样本吞吐高约67.9%，每步总耗时低约40.4%；相对 `8×2` 的总耗时仅低约2.5%。`16×1` 时准备/传输占每步总耗时55.0%，说明单纯增加微批的边际收益已经很小。进程报告的主机内存峰值约2.44 GiB；这不是整机并发内存需求或正式运行保护阈值。PyTorch allocated/reserved 与整卡占用也不同，整卡利用率需待采样 CSV 核对。

训练图 tile1 的全图推理使用 batch4，耗时0.337秒，输出约493万像素；该单次数字不用于推断整个验证流程的耗时。

## 下一门槛

1. 取得服务器原始 JSON 与 GPU 采样 CSV，核对运行期实际整卡利用率、占用、功耗及是否有其他进程干扰；这些文件的归档不阻塞新机制的设计。
2. 下一批可将 `16×1` 作为**暂定**吞吐配置，所有候选和对照一致使用；在正式长队列前的短流程检查训练损失、梯度、更新和稳定性。若不通过，回退到本次吞吐接近的 `8×2`。不同微批的有效像素 CE 分母、浮点归约及批依赖行为可能不同，不能直接复用 D21 指标。
3. 数据准备/传输占比提示后续可比较一次性批量传输和 CPU 预取，但无需为此再延迟方法探索。下一批新机制与所有对照须使用同一冻结配置，默认单种子；D21 旧结果不随配置改变而重算或改写。

本轮不需要下载数据、权重或安装环境。D21 的准确率和缺失 DSM 门槛失败结论保持不变。
