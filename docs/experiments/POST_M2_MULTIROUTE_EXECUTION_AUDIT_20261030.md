## 1. A0 很快，但速度的适用范围很窄

**代码已实现：512×512 图像确实进入 DINO 编码器；没有把整图预先缩小，也不是读取缓存特征。** `extract()` 调用真实 `encoder.forward_features()`，拿到全部 patch tokens。DINOv2 patch14 在右/下侧 replicate 补至 518×518，得到 37×37 特征网格；DINOv3 patch16 为 512×512、32×32 网格。均是冻结编码器、bfloat16 前向，只有 384→6 的 1×1 分类头训练。

| 部位 | 实际执行 | 对新计划的影响 |
|---|---|---|
| 数据裁剪 | 原始 RGB 的 512 裁剪、随机翻转，无低分辨率输入替代 | 旧 profile 确实涵盖真实 512 输入的冻结骨干计算 |
| 训练特征 | 全部 patch 网格，不是 CLS/全局平均 | 可以评价冻结 patch 表征的线性分割可用性 |
| 训练目标 | logits 双线性到 128×128，标签最近邻到 128×128，CE 仅训练小头 | **不是 512×512 全像素监督**，不能用它否定边界/小对象/高分辨率 decoder 路线 |
| 评价 | 512 窗口、stride256，logits 插值到512后累加，整图 argmax | 0.4066 秒对应实际 529 窗口预测路径，但不是端到端数据到完整评价报告时长 |
| 预测计时 | 包含窗口组装、传输、骨干/头、拼接、argmax、预测回 CPU | 不包含该次影像解码/加载、score/coverage 首次分配；CPU 混淆矩阵在正式 evaluate 另计 |
| 参数更新 | encoder `requires_grad_(False)`，只有小头 backward | 0.01093 秒/步不能外推 LoRA、last4、整骨干、双流联合训练、恢复模块或复杂 decoder |

源码定位：[加载/冻结骨干](https://github.com/66322/remote_sensing_frequency/blob/c22a046407daf42064cbb161429f2648c9b86d66/scripts/post_m2_a0.py#L174)、[完整网格与128监督](https://github.com/66322/remote_sensing_frequency/blob/c22a046407daf42064cbb161429f2648c9b86d66/scripts/post_m2_a0.py#L242)、[整图计时](https://github.com/66322/remote_sensing_frequency/blob/c22a046407daf42064cbb161429f2648c9b86d66/scripts/post_m2_a0.py#L284)、[真实评价与CM分段](https://github.com/66322/remote_sensing_frequency/blob/c22a046407daf42064cbb161429f2648c9b86d66/scripts/post_m2_a0.py#L487)。

`profile()` 每配置32次更新、前8次预热，共5个配置。其 `median_total` 定义是等待耗时中位数加计算耗时中位数，不是配对总耗时直接取中位数。显存峰值未对每个候选 reset，所以候选之间的 max memory 是累计高水位，不宜当作独立配置显存对比。这些限制不推翻已完成的冻结骨干吞吐证据；本次不建议为文档补正重复旧 profile。

全图 score 不除以 coverage 后再 argmax，对每个像素所有类别共同除同一正数不会改变类别结果，故此处不是准确率 bug。源码未见足以要求立即停止旧 A0 的科学/工程缺陷。

**A0 的结果只回答：在这套冻结骨干、线性头、128监督、Potsdam F0 分割协议中，DINOv3 是否比 DINOv2 更好。** 不能把它扩写成“DINOv3 无效”“结构恢复无效”或所有后续路线的总开关。DINOv3 尚未就绪时，使用既有 DINOv2 的独立几何、解码、优化和退化路线仍可以规划；不能静默替换旧 A0 模型。

## 4. 对多路线计划的具体建议

建议按不同瓶颈并行，而不是全都依附“换DINO→补头→再融合”。以下均为**重写版建议**，不预先承诺方法胜出。

1. **空间/边界分辨率路线**：固定 DINOv2，先用真正中间层或 RGB 高分辨率浅层分支，并用原分辨率标签监督。最小对照应包含线性/普通decoder、简单高分辨率skip、候选结构、对应打乱或去几何；Full边界和小对象指标单列，不拿 NoBoundary 主分数替代边界问题。A0阴性不停止此线。
2. **几何对应路线**：先诊断 DSM 平移、基准高度偏移、不同物理尺度的敏感性，再选一种相应机制；比较同容量空间、普通RGB–DSM融合、真实几何与错配几何。不得把 centered DSM 叫作 nDSM，不假设所有 DSM 都提供可靠物体高度。
3. **输入质量/恢复路线**：把 down4 识别为受控分辨率压力，不自动等同真实低分辨率传感器。比较普通低分辨率训练、简单插值/增强、强解码器、任务恢复；若声称超分贡献，记录恢复目标是否联合反传及它对分割的独立增量。独立退化必须在训练方案冻结后使用。
4. **额外知识/训练时多模态路线**：只有教师新增信息确实存在时再做蒸馏；比较普通监督、普通KD、拟议知识目标与同位置硬标签控制。强教师/高分辨率/多模态输入在训练期的成本须显式列出，测试期不偷用不可得模态。
5. **联合优化路线**：采用真实共同训练参数的基线，先分条件记录损失/梯度cosine/范数/更新暴露，才决定是否做梯度或动态采样干预。普通联合适应和简单均衡采样是必要强控制，避免 D27/M2 的“纠错条件率提高就等于总体改善”逻辑。
6. **泛化/协议路线**：独立地域、不同 GSD 或未见退化回答不同问题。外部数据为确认阶段服务，不必阻断开发阶段；但开发集预先知晓或频繁反复使用的限制必须写明。不能以多seed替代场景外推。

同一个新结构可以服务两类瓶颈，但第一轮不要把所有模块叠在一起。每条线预注册最小有用增益、伤害约束和强对照，负结果只关闭具体配方。胜出后再研究两条线交互；没有单独证据时，组合总分上涨不能识别贡献来源。

## 5. 双H100预算与停止条件

已读当前 `EXPERIMENT_PLANNING_RULES.md`。建议第一轮把资源用于更宽的匹配问题覆盖，默认 seed42；仅候选与必要对照成对复验 seed17。三seed不作为新默认配置。

- 先列**训练作业数、更新数、有效样本数、评价case数**，再根据各路径真实吞吐给墙钟估计。预算公式：`训练≈作业数×更新数×实测秒/步`；另加影像读取、固定评价点的整tile预测/CM/写盘、准备与启动。双卡并行总墙钟由每卡队列的较长者决定，不是简单把所有成本除二。
- 每GPU默认一条独立作业，GPU0/1按路线轮转或配对分配；固定分配记录，避免让路线与设备/并发数据等待系统性混杂。不要先多进程挤同卡来追占用率。
- 可先为每条线设计3–4个必要arm的单seed筛查，再只推进有机制差距的1–2条。2k适合已知小头的短筛；全骨干或新decoder不能仅为统一预算硬套2k并据未收敛结果关闭问题。统一的是配对公平和终止规则，不是所有架构相同步数即可公平。
- 对新真实路径复用匹配profile；不匹配的路径须测等待、H2D、encoder、decoder/loss/backward、评价和写盘，峰值内存每候选独立统计。若已有正式作业获得授权，按规则可在其首段采样，不能另开无必要训练探针，也不能冒称已事先比较。
- 共性工程错误首败即停派发；保留原栈，不继续批量失败。科学停止条件是未胜匹配强基线、机制控制无差距或预注册伤害约束失败；不把一条线阴性变为其他独立线自动停止。
- 不保证“几小时完成”或套用0.01093秒/步估计全部路线。应先交付准备表：已有/新增权重、许可与来源、依赖、真实输入/标签尺度、训练参数、计时范围、单/双seed成本、产物保存回收及停止条件。
